# Thailand Restaurant Receipt Reference Guide & OCR Edge Cases

## 1. Overview of POS Systems in Thailand
The vast majority of dine-in restaurant receipts in Thailand are generated by modern tablet-based or desktop POS systems:
* **Ocha POS** (Dominant in cafes, milk tea shops, and casual restaurants)
* **Wongnai POS / FoodStory** (Dominant in mid-tier restaurants, bars, and chains)
* **SilomPOS / FlowAccount POS** (Standard retail and mid-sized eateries)
* **Custom Enterprise POS** (MK Restaurants, Bar B Q Plaza, Central Restaurants Group)

## 2. Receipt Layout Anatomy

### 2.1. Header Section
* **Restaurant / Shop Name** (often large bold Thai/English text).
* **Tax Identification Number (เลขประจำตัวผู้เสียภาษี 13 หลัก)**: Indication of official tax invoice (ใบกำกับภาษีอย่างย่อ).
* **Branch Indicator**: e.g., `สำนักงานใหญ่` (Headquarters) or `สาขาที่ 00001`.
* **Table Identifier**: e.g., `โต๊ะ: T12`, `Table 05`, or `Takeaway / กลับบ้าน`.
* **Timestamp & Queue**: e.g., `20/10/2026 19:42:10`, `Order #0045`.

### 2.2. Line Items (Body)
* **Standard Line:** `[Quantity] [Item Name in Thai/English] [Total Price]`
  * Example: `2 ต้มยำกุ้งแม่น้ำ 500.00`
* **Multi-Unit Breakdown:** Sometimes formatted as `2 x 250.00 = 500.00`.
* **Modifiers / Customizations (0-price lines):**
  * Examples: `เผ็ดน้อย` (mild), `ไม่หวาน` (unsweetened), `แยกน้ำซุป` (soup on the side).
  * *OCR Rule:* Must be attached to parent item or ignored if price is 0.00.
* **Paid Add-ons:**
  * Example: `+ ไข่ดาว 15.00` or `+ เพิ่มชีส 25.00`.
  * *OCR Rule:* Can either be merged into the parent dish or treated as a sub-item.

### 2.3. Summary & Financial Footer
* **Subtotal (ยอดรวม / รวมเงิน):** Sum of line items.
* **Discounts (ส่วนลด):**
  * Member discounts (e.g., `-10%`).
  * Flat vouchers (e.g., `-100.00 THB`).
  * Restaurants differ on whether the discount is applied before or after the service charge (see PRD §4.2 `discountTiming`).
* **Service Charge (ค่าบริการ):** Almost universally **10%** in Thailand.
* **Value Added Tax (ภาษีมูลค่าเพิ่ม - VAT 7%):**
  * **Exclusive Mode:** Applied on `(Subtotal - Discount + Service Charge)`.
  * **Inclusive Mode (ราคารวมภาษีแล้ว):** Displays the VAT amount breakdown for informational/tax purposes, but does **not** add it again to the grand total.
* **Grand Total (ยอดสุทธิ / รวมทั้งสิ้น / Total Due):** The definitive amount that must be matched.
* **Rounding Adjustments (ปัดเศษสตางค์):** Occasional cash rounding adjustments (less common with PromptPay).

## 3. Receipt Extraction Schema

The schema below is supplied to Amazon Bedrock as a **tool-use input schema**, so the model must return JSON in this shape. The model returns **decimal Baht exactly as printed** on the receipt; the application converts every amount to integer satang immediately after parsing (ADR-012).

```json
{
  "restaurantName": "ร้านอาหาร ตัวอย่าง",
  "table": "T04",
  "date": "2026-10-20",
  "items": [
    {
      "id": "item-1",
      "name": "ต้มยำกุ้งน้ำข้น",
      "quantity": 1,
      "unitPrice": 250.00,
      "totalPrice": 250.00,
      "modifiers": ["เผ็ดกลาง"],
      "needsReview": false
    },
    {
      "id": "item-2",
      "name": "ข้าวสวย",
      "quantity": 3,
      "unitPrice": 20.00,
      "totalPrice": 60.00,
      "modifiers": [],
      "needsReview": false
    },
    {
      "id": "item-3",
      "name": "ชาเย็น",
      "quantity": 1,
      "unitPrice": null,
      "totalPrice": null,
      "modifiers": ["หวานน้อย"],
      "needsReview": true
    }
  ],
  "financials": {
    "subtotal": 310.00,
    "discounts": [
      { "label": "สมาชิก -10%", "type": "percent", "value": 10.0, "amount": 31.00 }
    ],
    "serviceChargeRate": 10.0,
    "serviceChargeAmount": 27.90,
    "vatRate": 7.0,
    "vatAmount": 21.48,
    "isVatInclusive": false,
    "roundingAdjustment": 0.00,
    "grandTotal": 328.38
  }
}
```

Field notes:
* `unitPrice` / `totalPrice` are `null` when illegible; `needsReview` is then `true`.
* `discounts[].type` is `percent` or `flat`; `value` is the percentage (for `percent`) or Baht value (for `flat`); `amount` is the Baht amount actually printed.
* Any `financials` field not printed on the receipt is `null` (e.g., no service charge line → `serviceChargeRate: null`).
* The example above uses discount before SC: `(310.00 − 31.00) × 10% = 27.90`, `(279.00 + 27.90) × 7% = 21.48`, total `328.38` (item-3 excluded until reviewed).

## 4. Prompt Engineering Guardrails

1. **Strict Zero-Hallucination on Prices:** If an item's price is smudged or cut off, output `null` for price and flag `"needsReview": true` rather than guessing.
2. **Quantity Unpacking:** When quantity > 1 (e.g. 4 bottles of Singha beer), the application layer can unpack the item into 4 individual single-quantity items so 4 people can each claim 1 bottle with a single tap (PRD §4.4). The model always reports the line as printed.
3. **Inclusive vs Exclusive VAT Detection:** If the receipt says `รวม VAT 7% แล้ว` or `VAT Included`, set `isVatInclusive: true` so our math engine does not double-charge tax.
4. **Report, Don't Compute:** The model reports printed amounts only. All calculation and validation is done by the shared math engine and Math Guard.
